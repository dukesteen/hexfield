# Cloudflare deployment review disposition

The [raw Claude review](deployment-review-raw.md) used the [pinned excerpt input](deployment-review-input.md) and [source manifest](deployment-review-manifest.sha256). Claude had no tools. A larger full-source request ended with a CLI execution error; this review covers the security-critical excerpts and the local checks below. The reviewed snapshot preceded the free-only decision and contained a TURN credential issuer. The raw review and its input remain unchanged; the final source state is recorded separately in the [post-review manifest](deployment-postreview-manifest.sha256). No production source changed as part of this review.

| Finding                         | Disposition                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1, failed TURN refund is silent | Confirmed in the reviewed snapshot, now removed. The final Worker does not issue TURN credentials, reserve quota, or call `quota.refund()`. Its `/api/turn` route returns 503. The finding no longer applies to deployable code.                                                                                                                                                                                                     |
| 2, refund after UTC rollover    | Accepted fail-closed behavior in the reviewed snapshot, now removed with TURN issuance. The reservation belonged to the previous day's row; refunding the new day would have created unearned capacity.                                                                                                                                                                                                                              |
| 3, no post-upgrade rate limit   | Rejected. `RoomCore.receive()` checks encoded frame size against `SERVER_WIRE_LIMIT`, keeps a per-session sliding one-second arrival list, and rejects the 31st message. The attachment saves and restores the arrivals and clock.                                                                                                                                                                                                   |
| 4, alarm scheduling unseen      | Excerpt limit, checked against `CloudflareRoom.#persistAndSchedule()`: it schedules the earliest unauthenticated join deadline or room idle deadline and deletes an obsolete alarm. The frozen adapter also sweeps expired sessions during restore and before upgrades and messages. Cloudflare alarm delivery time still needs real Worker observation; a late join frame fails the deadline check in `RoomCore.join()` regardless. |
| 5, attachment validation unseen | Excerpt limit, checked against source. `#readAttachment()` bounds serialized attachment bytes and basic shape; `RoomCore.restoreSession()` calls strict `isRoomSessionSnapshot()`, which validates exact fields, challenge, room ID, finite timestamps, bounded arrivals and peer key before restoring authority.                                                                                                                    |

Cloudflare's [rate-limit binding documentation](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/) says counters are location-local and eventually consistent. The connection rate binding is an abuse throttle, not exact accounting. Credential count and two-hour expiry in the reviewed TURN design did not bound relay traffic. Cloudflare's [TURN FAQ](https://developers.cloudflare.com/realtime/turn/faq/) prices egress by GB and states a 1,000 GB shared free tier. [Budget alerts](https://developers.cloudflare.com/billing/manage/budget-alerts/) notify after spend crosses a threshold; they are not a provider-enforced stop. The final Worker removes the TURN issuer and key bindings and returns 503 from `/api/turn`; the deployed client build leaves the default TURN endpoint empty. Cloudflare STUN and direct connections remain available. Do not restore TURN issuance or create a TURN key without a verified provider-enforced zero-overage traffic cap.

The [Workers static-assets routing guide](https://developers.cloudflare.com/workers/static-assets/routing/single-page-application/) supports selective `run_worker_first` with SPA fallback, matching the Wrangler route shape. A real Worker smoke test remains responsible for verifying WebSocket 101 behavior, hibernation alarms and close timing under the chosen compatibility date.
