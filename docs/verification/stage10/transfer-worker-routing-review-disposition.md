# Transfer worker and routing review disposition

This follows `transfer-worker-routing-review-raw.md`. The reviewed manifest predates these fixes. This is a scoped review disposition, not milestone acceptance or a deployment record.

| Finding                                            | Disposition and evidence                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Whole-artifact timeout                          | Fixed. The channel uses a 30-second inactivity deadline for each chunk, with bounded retransmission. It no longer requires a 16 MiB artifact to finish within 120 seconds. Channel tests cover slow chunk delivery.                                                                                                                                                             |
| 2. Lost first frame and duplicate acknowledgements | Fixed. Retransmission reuses exact bytes; receivers acknowledge exact duplicates. Link and browser generations reject delayed callbacks from replaced connections. Link tests exercise offline notification and channel replacement.                                                                                                                                            |
| 3. Unbounded retired-route grace                   | Fixed. `P2PSession` invokes `onCertifiedNonMembershipCommit`; `online-game.ts` prunes retired devices at ordinary committed heights and emits changed routes. Transport tests cover expiry.                                                                                                                                                                                     |
| 4. Duplicate destination route                     | Already rejected upstream. `transfer-membership.ts` checks other seats' device routes and reserved controller, device and master keys before authorization. The transport projection remains an additional check.                                                                                                                                                               |
| 5. Chat and lobby traffic                          | Chat already selects recipients from `allowedSenders()` and rechecks that set after persistence. `online-room.ts` now disposes the lobby controller once the game becomes active. Chat/startup/manual-room tests passed.                                                                                                                                                        |
| 6. Structured-clone backing buffers                | Fixed. `prepareOnlineWorkerRequest` detaches ordinary canonical data and copies only a bootstrap view's bytes. Shared bootstrap buffers are rejected. Client/runtime tests check subarrays, later caller mutation and shared memory.                                                                                                                                            |
| 7. Concurrent heavy exports                        | Fixed. Save and bootstrap exports share the one-heavy-request slot with imports. Bootstrap encoding enforces the 16 MiB bound. Client/runtime tests exercise slot admission and control capacity.                                                                                                                                                                               |
| 8. Initial import shutdown and timeout             | Cooperative cancellation added to destination creation and operations, and shutdown aborts that signal before draining. Heavy requests have a ten-minute default deadline. Synchronous cryptographic work cannot be interrupted in the middle of a JavaScript call; shutdown observes cancellation at subsequent checks. This is not a claim of bounded subsecond cancellation. |
| 9. Repeated control-history replay                 | Fixed within routing. A suffix containing control/cheat entries triggers one verified full replay for the batch, rather than one replay per suffix entry. Ordinary entries advance incrementally.                                                                                                                                                                               |
| 10. Commit-hook reentrancy                         | The suspected reentry was not found. The replica's peer-change listener enqueues its pulse; it does not execute consensus inline. Routing installs state before notification and isolates listener exceptions. The final old-route commit precedes retirement.                                                                                                                  |
| 11. Public reply ownership                         | Fixed. Offer/readiness replies pass the transfer schema and a public copy; snapshots expose an explicit public shape. Activation returns the game identifier plus that public snapshot. No destination keys enter the browser coordinator.                                                                                                                                      |

The source retains durable historical credentials for verified recovery/return and evidence. Retained bytes do not restore voting rights: certified authority and retirement checks govern every resumed signer. In-memory owned material is wiped on retirement. Deleting the durable record blindly would break intended recovery flows, so the informational deletion suggestion was not adopted.

The new caller uses a separate authenticated two-device link scoped to the signed invitation, attempt, genesis and both devices. It persists the chosen destination and explicit approval before dependent output. Destination promotion requires a verified final certificate and shuts down the isolated importer before reporting success. A channel acknowledgement only confirms delivery. A separate receipt names the exact certified authorization and outcome, which the source checks against its worker.

Receipt ordering is deliberate: after the source worker confirms a certified activation or cancellation, the source marks that local attempt finished even if final-bootstrap delivery or the destination receipt is unavailable. The UI remains in `awaiting-receipt` or `cancelled-awaiting-receipt`; it does not report destination completion. On activation, the destination persists promotion and invokes its game-open callback before sending the receipt, so loss of the receipt does not strand a promoted destination. Only a matching receipt lets the source display the final `activated`/`cancelled` phase. The source browser regression also verifies that a certified cancellation with no channel permits a fresh invite; it uses a fake worker and is not a native transfer test.

Generic receiver failures do not fabricate cancellation. Only a certified cancellation, or a local source cancellation before any approval, can report cancellation. Lost final receipts remain retryable after importer shutdown; tests check completion and an exactly-once promotion callback after retry.

Focused verification at this checkpoint: channel 7 tests, client/runtime 17 tests, room/startup/chat 25 tests, browser/link/exchange 10 tests, public records 2 tests, query cleanup 6 tests, and a genuine worker import/restart/promotion test passed. These counts describe separate focused runs, not one full-suite run. Native browser handoff, current-protocol complete-game audits and full milestone acceptance remain pending.
