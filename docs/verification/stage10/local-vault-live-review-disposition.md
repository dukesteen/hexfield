# Live vault review disposition

The [raw review](./local-vault-live-review-raw.md) covers the pinned pre-fix [input](./local-vault-live-review-input.md) and [manifest](./local-vault-live-review-manifest.sha256). The [post-fix manifest](./local-vault-live-review-postfix-manifest.sha256) records the revised core files. The reviewer had no tools or runtime records.

1. **Late owner after Lock:** Fixed. One opening parent lease is shared among concurrent scopes. A lock epoch rejects an owner or child scope granted after Lock began; the opening owner closes before it can be retained. Tests cover simultaneous first scopes and Lock overtaking an opening scope, including zero retained Web Locks.
2. **Lock request during unlock:** Fixed as a bounded failure. Lock advances the epoch before testing busy state, so an in-flight unlock closes its newly acquired lease. A waiting exclusive migration can abort after 30 seconds instead of waiting forever. The controller reports a busy error for retry; it never treats a failed remote close as permission to proceed.
3. **Room opening during Lock:** Fixed. The lock callback stops partial worker, transport and identity ownership, then waits for the open attempt to settle. Every awaited opening stage checks cancellation, and worker creation checks the live scope before reading its handoff. The callback retains the lease until cleanup finishes.
4. **Stale mode after another tab changes the vault:** Fixed. Successful migration broadcasts a change. A tab closes owners and reloads public mode/generation; stale or locked acquisition errors also refresh status. Unlock refreshes before rejecting a cached clear mode.
5. **Initial status read failure:** Fixed. With no live owner or scope, a later `ready()` retries the metadata read.
6. **Unbounded closer wait:** Fixed with a 30-second close deadline. On expiry the controller keeps the owner and reports an error; it does not drop a key while a signer might still run.
7. **Settings while locked:** The global settings repository now opens a short vault-bound store per operation. The root theme uses system defaults while locked, Settings remains reachable, and the vault query invalidates settings after unlock. Root added an alert for controller error state.
8. **Optional vault arguments:** Production protocol-worker entry points acquire an owner before identity or journal access. Optional factories remain for injected test stores and direct focused tests. This is an internal seam, not an alternate browser unlock path.
9. **Worker handoff and archive store:** Both one-shot worker entries now validate exact handoff shape before acquiring a lease. The archive store closes before its owner, including failure.
10. **Full-save error type:** Vault acquisition failures map to stable full-save locked/busy client errors. Root separately removed capsule passphrases from TanStack mutation variables and clears form inputs on submit.
11. **Double close:** `VaultOwnerLease.close()` is idempotent. Store and owner cleanup can race the controller's lock cleanup without restoring a closed key.
12. **Dispose after failed signer close:** Retained intentionally. If a closer fails, `dispose()` rejects and the controller remains in an error state with the owner held. Marking it disposed or dropping its channel while a signer is still live would hide that failure and make a later safe retry harder. New scopes are refused until the closer succeeds.

Storage build, web TypeScript check and scoped lint pass. Focused tests pass: 10 storage vault tests, 7 controller tests, 12 worker-client tests, 7 protocol-worker tests, 7 runtime tests, 4 room-roster tests, 4 full-save-client tests, 3 archive-client tests and 2 settings-hook tests. Full-save inventory and worker tests pass separately, 2/2. The [native vault check](local-vault-browser-acceptance.md) also passes enable/reload/unlock, wrong-key rejection, cross-tab room closure, rotation, disabling protection and public identity continuity. A vault-enabled native game restart and finish remains a separate check.
