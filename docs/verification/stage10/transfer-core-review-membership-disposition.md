# Transfer core review: membership disposition

This disposition covers findings 1, 2, 3 and 5 from `transfer-core-review-raw.md`.

| Finding                                            | Result                         | Evidence and action                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------------- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Stale recovery root can reclaim a returned seat | Fixed                          | Return authorization now selects the newest certified root for that departed seat, then requires the statement to name that root's final authorization and activation. The transfer regression runs two recovery/return generations: a return signed with the first human key and R1 is rejected after R2, while the current R2 lineage remains eligible.                                                                                                                                                                                                                                                                                                                                            |
| 2. `validUntilSeq` is not rechecked at activation  | Intentional by approved design | [Seat transfer design, §1 and authorization rules](seat-transfer-design.md) says the bound controls certification of the authorization only. Once certified, the pending authorization persists until exact-parent activation or cancellation; no local or network timer expires it. No activation check was added.                                                                                                                                                                                                                                                                                                                                                                                  |
| 3. Transfer encryption point can be reused         | Fixed                          | Fresh-key validation now reserves encryption points from every recorded authorization, including cancelled transfers. The transfer regression verifies a point from a cancelled authorization cannot be reused.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 5. Recovery amendment scope and recovery kinds     | No defect found                | `recoveryChangeSchema` accepts only `recovery-authorize` and `recovery-activate`. The authorization validator requires amendments to name the current pending authorization, preserve `departedSeat`, keep the same frozen replacement-seat set, and retain exact current recoverers/host. The transfer tracker therefore only updates the root's final authorization. Existing recovery amendment tests cover latest-ref activation and key reservation; the transfer test now asserts amendment changes only the root's final authorization. Recovery is restricted to verified games, and transfer history is required on the v4 log path. There is no recovery-cancel variant to strand a route. |

Focused validation: `pnpm exec vitest run packages/protocol/src/transfer-membership.test.ts`.
