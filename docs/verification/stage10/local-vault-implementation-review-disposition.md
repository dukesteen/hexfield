# Local vault implementation review disposition

The source-only Claude review used the immutable inputs and hashes in `local-vault-implementation-review-{brief,input,manifest.sha256}`. Its raw output is preserved in `local-vault-implementation-review-raw.md`. The changes below were made afterward and are not represented by that pinned source snapshot.

| Finding                                            | Disposition                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Deletion waits behind a lifetime vault owner    | Confirmed and fixed. `withExclusiveVault` now requests the exclusive lock with `ifAvailable`; deletion returns `busy` while an owner is live and succeeds after it closes. It does not queue behind a lifetime owner or weaken the exclusive deletion fence. A focused test checks both outcomes.                                                                                                                                                                                |
| 2. Worker key handoff can queue behind migration   | Confirmed as a liveness risk and fixed with a fail-fast shared `ifAvailable` owner request. The worker still obtains its own shared lease and checks the handoff against current metadata; a queued exclusive migration returns typed `busy`, so the caller can retry after migration. The test lock manager now models named shared/exclusive FIFO locks, and a regression exercises that ordering.                                                                             |
| 3. Journal may pin inside an IndexedDB transaction | Not present in the complete source. `IndexedDbProtocolJournal.#database()` awaits `VaultRecordAccess.pin()` before returning a database to every operation; the review excerpt omitted this method. A fresh default-off journal's load and initialize paths remain covered by the journal tests. No behavioral change was made for this finding.                                                                                                                                 |
| 4. `abort()` hides an already failed commit        | Confirmed and fixed in vault migration and transfer stage/readiness transactions. Abort is guarded so the original failure is rethrown even when the transaction is already closed.                                                                                                                                                                                                                                                                                              |
| 5. Vault errors needed by future UI are untyped    | Addressed for the identified boundaries: stable `VaultError.code` values now distinguish closed, busy, changed, stale generation, locked, invalid key, corruption, identity missing/mismatch, weak passphrase and unavailable Web Locks. Authentication failures carry the offending record key. A malformed vault metadata test asserts `corrupt`. Storage remains unexposed in the app; later UI integration should map these codes without interpreting free-form error text. |

The vault is default-off and has no app unlock or settings flow yet. No vault-enabled browser acceptance is claimed. A separate native browser check exercised default-off hooks during public save export, import and reload. The storage-specific check passed 50 tests in five suites; `@cp2p/storage` build, `typecheck:tests`, scoped type-aware lint, and formatting check passed. The previous CI's three IndexedDB version failures are covered by the v5 fixture update (future upgrade uses v6); that focused suite passed 11/11. A subsequent storage review moved deletion's generation assertion before its transaction writes and added a race check that closing during decryption cannot return plaintext.
