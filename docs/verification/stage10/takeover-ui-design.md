# Takeover approval and local presence design

The current `submitRecovery(change)` accepts a complete signed `RecoveryAuthorization`. Its public validator checks the old quorum, escrow eligibility, fresh replacement keys, exact parent, host signature and replacement-key signatures. Ordinary consensus then votes for any valid authorization. None of those signatures says that the other remaining players chose to replace the human. The game also has no signed takeover policy or certified `SEAT_OFFLINE`/`SEAT_ONLINE` entry today.

## Consent and voting

Keep the existing old-voter quorum certificate and recovery wire format. The plan calls for a genesis-signed takeover policy, `{mode:'vote'|'auto', afterSeconds:number|'never'}`, bound through the frozen lobby agreement. That field does not exist yet. Until its migration is complete, this facade accepts an explicit vote-mode request only; a local caller option must not silently select auto mode.

In vote mode, each honest remaining voter must explicitly approve before **its own** key signs a positive vote for the exact `RecoveryReadiness` statement at the current parent. The target's own voter key is closed by default. This is a local signing rule, not an extra public signature set or a veto for each survivor. The old quorum remains the sole public authorization threshold. The host and fresh replacement-key signatures keep their existing roles; neither is a user approval. A still-online target plus two willing survivors can form a valid old-quorum certificate. That is permitted by the existing strict-agreement rule and does not add a new ability to expose the target's own master.

The local consensus gate is separate from public replay validity. Compose it with the timer gate in the single `ConsensusController.beforePersist` callback. For every **newly signed non-nil local vote**, find its retained proposal, then reject a `recovery-authorize` value unless a local approval matches the entire canonical statement, current parent and controller key generation. This scan covers proposal receipt, local proposal, round timeout, locked/valid proposal reuse and every other reducer path. It runs before safety CAS, memory assignment or effect emission. A refusal is transient `recovery-approval-required`, never an invalid-proposal strike or objective accusation. Nil votes and previously durable votes may proceed; restore retransmits already persisted votes. Activation uses the mandatory certified private checks and does not request a second takeover approval.

The first slice retains approval in memory. Restart conservatively clears it, so any **new** positive vote needs another click. A previously durable vote may still retransmit; the UI must not promise to undo it. A new parent requires a new preview and click. Keep at most one pending approval candidate per parent, ignore stale responses without striking the sender, and let the user decline by leaving the gate closed. Consensus round timers can move past a declined proposal; the gate never manufactures a positive vote.

## Candidate and facade API

For this slice, `previewRecoveryAuthorization(change)` accepts a complete signed `recovery-authorize` change and validates its exact current parent, authority, escrow roster, replacement keys and signatures without gossip. It returns the canonical statement hash, parent, departed seat, host, bot level, affected seats and recoverers for the UI. It may run while the engine waits for an offline player's command or random contribution. It rejects pending recovery, terminal result, insufficient old quorum, absent escrow eligibility, stale parent or an unsupported roster. It does not require an idle engine phase.

`approveRecoveryAuthorization(change)` is the explicit vote-mode UI action. It revalidates the same change inside the replica's serialized queue and records only its parent, statement hash and local key generation. `clearRecoveryApproval()` closes the gate for new votes. `submitRecovery(change)` remains the low-level fully signed input and cannot bypass the vote gate. `requestTakeover(departedSeat, botLevel)` is the host's explicit action. It derives terms from certified authority, reserves fresh replacement keys and the signed authorization in the durable recovery store, approves the host's own vote, then submits. A restart loads the exact reserved authorization rather than generating another key for the same parent. The other voters discover a validated candidate through their session update and approve it locally. Progress comes from the certified epoch/pending authorization and existing recoverer/check status. The facade does not expose masters, shares or replacement secret keys. Once authorization certifies, the existing participant handles release and activation.

The statement remains bound to its original certified parent throughout preparation and send. If the head changes, discard the candidate and local approval. Never rebase a partially prepared change or reuse its replacement keys in a new statement. Returning authenticated target contact clears the local candidate immediately. If a vote was already persisted, local cancellation cannot erase it; a certified competing online entry decides the public ordering.

## Presence and auto mode

Track only authenticated current voter links from `Transport.peers()` and `onPeerChange`, including the local voter. A local monotonic observer accumulates offline time only while the target is absent **and** the currently reachable voters meet the old quorum. It pauses while quorum is absent and resets when the target returns. Restart begins a fresh full interval; neither a peer timestamp nor the signaling server's room list restores elapsed time. Two- and three-human games have no eligible escrow takeover and remain paused when a voter is missing.

In auto mode, the same pre-CAS local vote gate requires this observer to exceed `afterSeconds` for the exact target while quorum is present. This is an honest-voter admission rule, not a replay or accusation rule. The host may prepare a new exact-parent authorization after the threshold. All peers still verify signatures, escrow eligibility, current membership and the old quorum certificate. If the target reconnects, clear the candidate and refuse new positive authorization votes. Presence can delay recovery but must never reduce the quorum. `afterSeconds:'never'` disables local takeover preparation and voting.

## Certified presence entries

Docs 10 names `SEAT_OFFLINE` after 15 seconds and `SEAT_ONLINE` on return. Neither action exists in the current membership schema. Add them as state-preserving certified membership entries with no change to voter authority or epoch. Their certificates establish a shared ordering and UI status, not objective proof of wall-clock elapsed time. Honest voters admit `SEAT_OFFLINE` only after local authenticated absence; `SEAT_ONLINE` requires the returning current controller's signed presence statement. A later online certificate clears the public offline marker and changes the parent, so an old takeover statement and approvals cannot be reused. Local observed return closes the vote gate immediately while that certificate is pending. A concurrent already-durable vote cannot be undone; whichever conflicting entry certifies first controls the next parent.

The first safe UI slice may show local presence before these entries exist, but it must not claim certified offline status. Full Docs 10 behavior needs the entry schemas, replay projection and the signed takeover-policy migration. Do not accept caller-supplied timestamps as authorization evidence.

## Focused checks and ownership

- Pure statement preview: exact affected seats and recoverers; active engine pending input accepted; pending recovery, 2/3-human, missing escrow, stale parent and terminal result rejected.
- Four-human vote mode: each honest survivor withholds its own positive vote until a click. The existing old quorum still decides authorization; no new all-survivor signature rule is introduced. Changed parent, host, level or replacement key invalidates local approval.
- Consensus: a valid but unapproved signed proposal produces no new local safety write, memory change or broadcast vote on proposal, later round or locked-value re-entry. Exact approval permits the vote; restart clears the gate for new votes. Timer and approval checks both apply to the same transition.
- Presence: pause below quorum, resume after quorum returns, reset on target return/restart, and never turn a local clock rejection into replay or accusation invalidity. Certified online/offline entries preserve engine state and do not alter quorum.

The current protocol slice owns the authorization preview, composed local vote gate and durable host request. The later policy/presence slice owns signed genesis policy and replayed presence entries. Web owns the approval prompt and presence display. The certified recovery participant and private installation paths remain unchanged.

## Exact policy and presence migration

Add a mandatory `takeover: { mode: 'vote' | 'auto'; afterSeconds: number | 'never' }` to `LobbyState` and `GenesisBody`. The numeric value is an integer from 15 through 86,400 seconds; new rooms default to `{ mode: 'vote', afterSeconds: 120 }`. The UI can offer 30, 60, 120 and 300 second presets plus `never`, but both the host request and every local voting gate read the signed value. The host signs it in `LOBBY_CONFIG`; the frozen lobby state's hash and every freeze ACK then bind it. `validateGenesisOnlineStart` must compare `body.takeover` canonically with the verified freeze agreement before genesis consent. `OnlineCeremony` copies only that frozen value into its draft. Do not infer a policy from a local setting or from the number of peers currently connected. The `never` value disables takeover preparation and positive authorization votes in either mode.

This changes the signed genesis body, `gameId`, every later `genesisDigest`, and the lobby state hash. Bump `PROTOCOL_VERSION` from 2 to 3 and reject old verified saves at open with a visible "unsupported game version" result; do not label them generically corrupt or add a v2 interpretation that silently supplies a default. Update `types.ts`, `schemas.ts`, `lobby-types.ts`, `lobby.ts`, `genesis-online-start.ts`, `online-ceremony.ts`, and the simulation and verified fixture builders together. The simulation helper supplies the explicit default so its fixtures remain deterministic after their expected hashes are updated. Resume checks the persisted freeze, genesis and version as one set. One-human plus bots remains valid, but cannot request escrow takeover.

Extend the strict `membership.change` schema with `{kind:'seat-offline', seat}` and `{kind:'seat-online', proof}`. Audit every branch that currently assumes the only variants are authorization and activation, including candidate derivation, recovery gossip, pending-input priority and the replay projection. The online proof is signed in domain `cp2p/v3/seat-online` over `{genesisDigest, epoch, parent:{seq,hash}, seat, generation:{seq,hash}, offline:{seq,hash}}`. The validator resolves that seat's **current active human controller** from the certified parent, checks its activation generation and verifies the signature. An original key cannot announce a return after replacement. `seat-offline` needs no signature from the absent seat; the ordinary elected entry signature and old-quorum certificate authorize the shared observation. Only an active human not already marked offline is eligible. No incoming timestamp establishes absence.

Keep certified presence in `RecoveryState.offline`, sorted by seat, as `{seat, since:{seq,hash}}`. The offline entry's own certified ref becomes `since`; a later online entry clears that marker. Both actions preserve engine state, crypto context, authority, voter set and epoch. Their entries still advance the certified head and invalidate an authorization bound to the old parent. Recovery authorization requires the target's offline marker and a genesis policy other than `never`; activation clears its marker. The public validator checks these facts and signatures, never elapsed local time. A future voluntary live transfer should have a distinct signed action; it must not bypass the takeover policy through `recovery-authorize`.

Add a local monotonic absence observer to `ReplicatedLog` using only authenticated `Transport.peers()` and `onPeerChange`. It tracks current human voter keys from certified authority. The target's return immediately resets its elapsed interval and closes any uncommitted approval, candidate and local intent. Absence time toward takeover accrues only while the target is absent and reachable current voters meet the unchanged old quorum. With fewer reachable voters it pauses; after restart it starts at zero. If the injected clock moves backward, reset rather than crediting time. Locally offer a `seat-offline` candidate after 15 seconds of absence when quorum is present. In two- and three-human games a missing voter prevents certification, and the takeover validator separately rejects the insufficient survivor set.

Compose the presence check with the existing timer and recovery gates in `ConsensusController.beforePersist`. Check every newly signed non-nil local vote for `seat-offline` against 15 seconds of observed absence, target still disconnected and quorum currently reachable. `seat-online` needs its public signed proof, not an elapsed-time gate. For `recovery-authorize`, require the certified offline marker, the signed `afterSeconds` of quorum-qualified local absence and target still disconnected. Vote mode also requires the existing exact-parent user approval. Auto mode permits the positive vote after the same observer threshold without a click. The host's automatic request uses the lowest active remaining human seat as a deterministic initiator, and still reserves fresh keys durably before output. A target return cancels only future local signing and uncommitted intent; it cannot erase a persisted vote. Replay, objective accusations and certificate validation never consult the observer.

Focused migration tests need a frozen lobby ACK and genesis with the same policy, mutation rejection at both boundaries, and a visible v2 save rejection. Certified offline/online entries must leave state and membership unchanged while changing the head and offline marker. The online proof must fail with a stale parent, old controller generation or another offline marker. With a virtual clock, test the 15-second marker boundary and multiple signed takeover thresholds, including 30 and 120 seconds, quorum-loss pause, target-return reset, restart reset, and no safety CAS before local eligibility. Finally certify one four-human vote-mode takeover after approval, and show two- and three-human departures remain paused without reducing quorum.
