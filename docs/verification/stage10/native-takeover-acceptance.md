# Native takeover and return checks

Full lifecycle acceptance is still open. These checks used protocol v6, signed signaling envelope v2, one installed Chromium process with four isolated contexts, real WebRTC, and localhost signaling on port 8909. The isolated source checkout was `/private/tmp/hexfield-takeover-acceptance` at baseline `8000f80` with the return fixes overlaid. `native-takeover-source-manifest.sha256` pins the initial full attempts; later attempts have separate manifests below.

The opt-in test is `apps/web/tests/online-takeover.e2e.ts`. It requires genuine setup, a turn number above zero before departure, certified recovery, an actual certified command from the recovered bot, return activation with fresh authority, and an actual certified command from that returned seat. The extended test has a 600-second total cap and keeps the default 10-VP target. After return it drives each human seat with RandomBot using that seat's own private state, with a 1,500-command cap and a 300-second finish deadline. It requires equal terminal heads and results plus independent complete, clean audits in all four active human contexts. This extension has not reached gameplay in a native run.

Observed results:

- A startup-only check passed in 38.4 seconds. Four humans reached the game route. This was concurrent with a separate functional headless crypto game, so the duration is not performance acceptance.
- An uncontended full attempt reached certified recovery, an actual bot command, and return activation. It then failed because the test read the game registry immediately after the destination URL changed, before the new screen loaded. Source UI showed the completed move; no page errors occurred. The test now waits for the game screen before reading the session.
- The next full attempt retired before opening. All four peers remained authenticated and signaling was ready. Every public startup snapshot reported `online-ceremony-retired`; there were no page errors. The former code lost the reason, so this result does not prove a timeout or a dispute.
- After adding durable retirement reasons, a startup-only check passed in 26.2 seconds. No retirement occurred in that run.

Logs remain at `/private/tmp/hexfield-takeover-v6-startup-diagnostic.log`, `/private/tmp/hexfield-takeover-v6-uncontended-native.log`, `/private/tmp/hexfield-takeover-v6-return-ready-native.log`, and `/private/tmp/hexfield-takeover-v6-reason-diagnostic.log`. Browser contexts and the test-owned Vite server closed after each attempt.

Source inspection found that the old timeout covered the whole ceremony, although docs/09 requires 20 seconds per step. The subsequent deadline change uses a durable monotone phase and start time. It is outside the native manifest above. Its virtual-clock tests cover a total ceremony longer than 20 seconds, same-phase retry and restart without deadline renewal, and post-consent waiting. A startup-only check on the final reviewed deadline source passed in 20.0 seconds after commit `3cfc853`; all four contexts reached game routes. `native-takeover-phase-startup-manifest.sha256` pins that overlay and its isolated-only early-stop test variant. The log is `/private/tmp/hexfield-takeover-v6-phase-startup.log`. This check does not establish takeover, return, a fresh-authority command, or terminal audits.

Two full attempts on the final phase-deadline source retired during deck setup. The lifecycle-only attempt took 32.7 seconds and the extended terminal attempt took 29.0 seconds. All four contexts reported `online-ceremony-timeout:deck`, authenticated peers, ready signaling and no page errors. Neither attempt reached departure, recovery, return or audit. The logs are `/private/tmp/hexfield-takeover-v6-full-phase.log` and `/private/tmp/hexfield-takeover-v6-terminal.log`. The lifecycle-only attempt used the full test hash recorded in `native-takeover-phase-startup-manifest.sha256`, without the isolated startup-only variant. `native-takeover-terminal-source-manifest.sha256` pins the extended attempt. Native execution needs `NODE_OPTIONS=--conditions=@cp2p/source` in this isolated checkout.

The 20-second deadline covers the whole deck setup phase. This matches the enumerated step 5 in docs/09, which collects every configured deck's ordered passes. No deadline increase or per-pass renewal was applied. Source inspection found that each coordinator advance reconstructs and verifies the accepted deck-pass prefix again, and a newly accepted pass is applied both by its slot validator and by the transcript loop. This is a performance suspect, not yet a measured cause of either timeout. Full lifecycle acceptance remains open.

After the reviewed coordinator prefix cache, a full attempt retired at 31.7 seconds. Peers 0, 1 and 2 reported `online-ceremony-timeout:deck`; peer 3 had reached consent. This attempt overlapped a separate stub runner during startup and does not establish uncontended runtime performance. Its log is `/private/tmp/hexfield-takeover-v6-prefix-terminal.log`, pinned by `native-takeover-prefix-source-manifest.sha256`.

The next, uncontended timing run completed startup, genuine mid-game departure, certified recovery, an actual recovered-bot command and fresh-key return activation. It failed after 2.8 minutes because the readiness assertion waited for the `Game info` summary inside a closed menu to become visible. The returned page was already displaying the game with seat 0 controlled locally. No page errors occurred. The test now waits for the visible game-menu summary and expands the resource timing buffer before navigation, so the returned page's actual registry module remains observable. This run did not certify a command from the returned key or reach terminal audits. Its log is `/private/tmp/hexfield-takeover-v6-timing-terminal.log`; `native-takeover-timing-source-manifest.sha256` and `native-takeover-timing.patch` record the isolated instrumentation.

That bounded instrumentation captured the first seven accepted deck passes on each peer by 10.6 to 12.6 seconds into deck setup. Observed shuffle-pass validation took 183 to 226 ms, local shuffle generation 219 to 264 ms, lock validation 26 to 29 ms and lock generation 39 to 42 ms. Maximum observed worker event-loop lag was 133 to 204 ms. Repeated identical progress notifications exhausted the 200-event cap before the last pass, so these data cannot establish the complete deck duration. The gaps between accepted passes are larger than the measured proof work. Source inspection found that a valid future pass arriving before its predecessor can be dropped until a one-second resend; this remains a candidate explanation until send/arrival timing confirms it.

A corrected full trace is now running without a competing local test workload. It keeps the same protocol, proof checks, 20-second phase deadlines, default 10-VP target and bounded terminal checks. Its isolated diagnostics log changed progress states, lifecycle milestones and finish progress without keys or private hands. `native-takeover-timing-v2-source-manifest.sha256` and `native-takeover-timing-v2.patch` pin this run. The log is `/private/tmp/hexfield-takeover-v6-timing-v2-terminal.log`. Its terminal result is pending.
