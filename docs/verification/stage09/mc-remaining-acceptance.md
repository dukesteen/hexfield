## Bounded M-C closeout matrix

Use targeted checks rather than replay-count inflation:

1. Preserve the accepted Stage 06 180-game report; run focused protocol, storage, and app checks affected by the migration.
2. Add a small deterministic real-crypto scenario matrix: one case per distinct chaos mechanism, with focused assertions for the affected invariant. Do not repeat every Stage 06 seed under expensive crypto.
3. Run 5–10 complete games across human, hosted-bot, and recovered-bot authority; require successful complete audit and retain the certified history/report digest for each.
4. Close only missing cheat-table rows with targeted certified-trace tests. Keep the existing primitive tests as evidence for already-covered proof rejection.
5. Decide the two explicit budget issues: hidden-transfer proof time (currently failing) and long invitation/phone scan (currently over the size limit and unscanned). Keep shuffle/draw timings as passing evidence unless implementation changes.
6. Perform one full signaling-server browser game and record the exact browser contexts. Treat four independent browsers, Firefox/WebKit, external-network behavior, and phone scanning as explicit separate acceptance items if required by the unchanged Stage 08 criteria.

This matrix does not claim that implementation coverage equals acceptance: passing unit tests establish local invariants, while the listed browser and performance claims require their own recorded evidence.
