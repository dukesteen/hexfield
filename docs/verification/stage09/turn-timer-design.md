# P2P turn timer design

Verified sessions currently expose no timers: `VerifiedSessionDriver.next()` returns null, and its driver has no `getTimers()`. The simulation driver has process-local timers and stub `TIMEOUT` evidence. The engine already emits `Pending.player.deadline` and implements `TIMEOUT`, but the verified log has no mandatory timer evidence validator.

A deterministic timer-anchor map belongs in `LogContext`, separate from `GameState`. For each pending player deadline, the key from `session-timing.timerKey` identifies the uninterrupted interval. Genesis initializes the map. Applying a certified entry retains an anchor if the key, seat, phase, and duration still match; a new interval records that entry's `{seq,hash}`. State-preserving control and crypto entries do not refresh an existing interval. Separate discard seats and trade responses have separate keys. Replay rebuilds this map exactly.

Verified `TIMEOUT` evidence uses `kind:'proof'`, protocol `turn-timeout-v1`, and strict data `{pendingSince:seq,deadlineMs:duration}`. Mandatory log validation checks the active pending seat and phase, the exact anchored sequence and configured duration, and the engine transition. It never reads a clock or trusts `EntryPolicy.verifySystem` for this input. The duration must be a positive safe integer in milliseconds. A timeout requiring private hand data is not a system candidate; its owner submits a signed legal command with normal hand proofs.

Each replica observes an active anchor against its own monotonic `ProtocolClock.now()`. A new certified pending interval starts at local application time. After restart, replay recovers the same certified anchor but starts a conservative full local interval; a process-local monotonic reading cannot safely bridge a restart. This can delay a timeout, but cannot make one early. The UI uses that same local observation. No peer timestamp enters evidence.

Local time is an admission and voting rule, never a deterministic validity or accusation rule. Before a `ConsensusController` transition persists, it checks every newly signed local vote for a `TIMEOUT` proposal, including votes produced by round changes or justified proposals. An early value returns a transient result without saving a vote, striking a peer, caching an invalid proposal, or producing an objective accusation. Previously persisted votes can be retransmitted after restart. The sequencer offers its timeout only after its local deadline, and the two-second pulse retries. Peers reject when their local elapsed time is more than three seconds short of the configured duration. Very short durations need a positive elapsed floor so the tolerance never permits immediate timeout.

Focused tests should cover early rejection followed by a later successful vote, unchanged anchor through control/crypto entries, separate simultaneous discard timers, restoration with a fresh clock and no immediate vote, no generic proof callback bypass, and an owner-signed private discard when public counts are uncertain.
