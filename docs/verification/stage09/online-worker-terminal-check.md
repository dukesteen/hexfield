# Online worker terminal check

The focused Node integration test `apps/web/src/session/online-worker-terminal.test.ts` passed on 2026-09-27 in **40.1 seconds** (`vitest run` for that file only). It uses one genuine two-human certified game with a deliberately shortened three-point victory target. The test-only `onSessionsReady` hook attaches `OnlineWorkerRuntime` before the first game entry. Production `OnlineWorkerClient` and `OnlineWorkerSession` then receive the real certified snapshots through an in-process cloned-message port. The final state has a certified result; both peers complete the full audit, and the proxy exposes the same complete result and fairness facts. Snapshot fairness heads equal committed heads; verified moves advance while non-input deck-crypto entries do not increase that count.

The audit uses production `createSessionAuditJob` and `performAuditRequest`, with transferred master buffers and an in-process audit-worker port. This proves the job RPC, proof verification, complete report and UI proxy projection together. It does **not** prove native nested browser Worker construction or a default ten-point game. The existing default-ten-point acceptance trace and native standalone audit smoke are separate evidence. A dedicated nested-worker browser smoke is prepared as a follow-up and must be run in an existing supported browser before that boundary is accepted.

After adding structured cloning on the main worker port, the same focused test passed again in **40.1 seconds**. No production worker or protocol code changed for this test.
