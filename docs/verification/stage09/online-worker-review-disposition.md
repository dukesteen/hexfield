## Findings checked against current code

- **F1, confirmed, fixed after review:** session events received after closing starts are ignored, and already queued `ackSession` failures no longer invoke fatal termination during graceful shutdown. A reentrant session listener that starts shutdown also cannot queue a new ACK. Focused client regressions cover both overlaps; shutdown still processes its matching reply and terminates after the orderly close. Runtime close now sets its closed guard before session disposal. Its regression proves disposal emits no late snapshot and that pending work and storage closure finish before the shutdown reply.
- **F2, confirmed in snapshot, fixed after review:** runtime published `session.controllableSeats()` including hosted bots while `OnlineWorkerSession.sanitize()` rejects any nonhuman-local seat. Runtime now projects `[game.seat]` only if that seat is controllable; the existing hosted-bot fixture asserts this and that it never reads bot private state. Focused runtime and transport tests passed **10/10**. This is an availability fix, not a claim that the real-browser guest startup is resolved.
- **F3, partly confirmed, tested for consensus submissions:** capacity and temporary offline/send failures remain lossy without disconnecting, as required by the transport contract. The focused liveness regression sends a real `P2PSession` setup command through the worker bridge, drops exactly one outbound consensus `SUBMIT`, advances the protocol pulse, and verifies both replicas commit the same next head while no disconnect or bridge failure occurs. Durable consensus submits retry on the two-second replica pulse. This does not claim an automatic retry guarantee for every ad-hoc protocol response; other message classes need their own evidence before relying on retransmission.
- **F4, confirmed in snapshot, fixed after review:** `online-protocol-worker.ts` dropped malformed main-thread requests without a response, leaving the client pending until its 120-second fatal timeout. It now returns an immediate generic error only when protocol, bounded generation, safe positive request ID and known operation kind form a valid reply header. It does not echo the malformed body; unknown or unbounded headers remain unanswered. Three focused tests cover invalid body, oversized body and unsafe headers.
- **F5, fixed after review:** a halted startup event now stops output, clears the display proxy and requests graceful worker shutdown. Attachment and later startup events are fenced once halted. A regression pauses initialization, emits a halt, then delivers the late initialize/opening events: no transport is attached or freeze pinned, the halted state remains, and the worker terminates only after its shutdown reply. All eight startup coordinator tests pass. The close test now includes positive frame delivery before close and holds shutdown open while proving later output is blocked.
- **F6, not accepted as stated:** preserving a displayed `complete` status after a later lease or integrity failure could hide a real inability to certify or audit the terminal state. The current error status is conservative. A separate immutable result view would require its own correctness contract.

Claude's other concerns (long RPC timeout, pre-listener delivery, browser `MessagePort` behavior, and repeated real pin) are unproven by this excerpt review. They are useful focused test questions, not verified defects. The reviewed startup close test lacked a positive frame-delivery control; the strengthened post-review test is described under F5.

The implementation report records real host/guest start, hosted-bot start, resume and orderly close. Focused tests cover lease loss and worker crashes. Full migration acceptance, including a browser terminal audit and timer measurements, remains open. No runtime credentials or private records were included in the review bundle.

Post-review focused verification: `online-worker-runtime.test.ts` and `online-worker-transport.test.ts` passed 10/10 after F2; `online-protocol-worker.test.ts` passed 3/3 after F4. `online-worker-client.test.ts` passed 8/8 after F1. The new `online-worker-transport-liveness.test.ts` passed 1/1 after F3. Scoped lint and formatting passed for the F4 files. The concurrent repository test typecheck stopped on `online-worker-startup.ts:298` (TS2367 in another agent's in-progress startup edit); it reported no error in the F4 files.
