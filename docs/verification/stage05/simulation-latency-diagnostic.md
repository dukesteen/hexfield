# Stage 05 simulation latency diagnostic

The [current cockpit checkpoint](bench-1000-seed42-cockpit.json), measured once during the final audit on 2026-09-25, passes the Stage 04 budget: 28.32 ms per complete four-player game and 0.037 ms `apply` p99. It completed 1,000 games with zero failures on commit `ae91cad`, source fingerprint `c9d6ef79ed303d36bd07876c052dff39c2c319d7e5abdd173f95fa54fff853f5`, unchanged during the run. It used one worker, five separate warmups, Node 22.23.3 on macOS arm64, and disabled invariant diagnostics only for timing. No benchmark settings or engine code were changed for this measurement.

Earlier measurements remain evidence of host timing variation. The [Stage 04 acceptance benchmark](../stage04/bench-1000-seed42-acceptance.json) measured 28.03 ms per complete four-player game. After adding the public `resourcesProduced` event, runs measured 31.27, 32.23, and 31.62 ms. A sequential comparison against an isolated build of the accepted Stage 04 commit measured 30.58 ms baseline and 31.62 ms with the UI events. Those earlier runs exceeded the 30 ms target and are retained below rather than treated as passes.

All these runs used macOS arm64, Node 22.23.3, pnpm 10.7.1, one worker, five warmup games, seed 42, four seats, default rules, and `verifyInvariants: false`. This excludes the optional per-input invariant audit but retains validation, private updates, freezing, and rollback. The two controlled runs invoked the already-built simulator with `node tools/sim/dist/index.js bench --games 1000 --players 4 --seed 42` in each checkout; the other runs used `pnpm sim bench` with the same simulator arguments. Each run completed 1,000 games without a failure and reported `sourceUnchanged: true`. The turns, inputs, wins, dice histogram, and command counts matched exactly across builds.
