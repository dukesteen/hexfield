# Deck protocol foundation review

Review the attached implementation read-only. Do not run tools, write code, access
other files or contact external services. The user has approved project reviews.
Only source, design and deterministic public test fixtures are included.

This is the first part of Stage 07 Step 3, not acceptance of Stage 07 or a claim
that hidden draws are integrated into live sessions. The existing shuffle and
DLEQ helpers have been reviewed previously. New code implements signed ordered
shuffle/locking passes, deterministic per-deck secrets, partial unlock chains,
private owner decoding, public identity proofs and an immutable unlock outbox.

Check the mathematics and statement/context binding, substitutions, re-keying,
duplicate/identity points, wrong-slot/card/owner/epoch reuse, source restoration,
mutable inputs across awaits, persistence-before-return and malformed input.
Give concrete failing traces and file/line references, ranked by severity.
Assess test strength, including whether a negative test reaches proof verification

The remaining integration work will derive operations from the local certified
engine pending and verified setup. Shape validation alone is not authority to
decrypt. Public setup state is trusted only after replaying every signed pass;
neither incoming snapshots nor a peer-provided DrawOperation may authorize an
unlock. Integration must also enforce ordered one-time draw consumption, the
engine's exact base card catalogue, owner slot matching, and per-command reveal
proofs before voting. It will store protocol consequences in CryptoContext and
apply the owner's private identity only after certification. Those caller checks
are intentionally not claimed complete in this packet.

Setup contexts bind the frozen ceremony and full deck definition. Certified
creation contexts additionally bind genesis, epoch and anchor. Draw contexts
bind the completed setup hash, certified request parent, owner, position, slot,
ordered keys and initial point. Reveal proofs bind the full command, nonce and
parent. The definition maps physical identity to engine card kind; the caller
must compare that table to the agreed module catalogue.

The shuffle optimization precomputes window-4 tables for repeated public points.
It keeps Noble's secret-safe multiply path, all 64 rounds and identical proof
bytes, checked against three hashes generated by the original implementation.
Tables are local to a call, with at most 128 cards. Check for changed soundness,
secret-dependent work or hidden unbounded caches. Node measurements improve
six sequential 25-card prove/verify passes from about 14.7s to 6s. An initial
Chrome worker run of all signed passes remains above the planned 3s target.
The target is still open; no reduced soundness or parallel-speed claim is used
to mark it complete.
