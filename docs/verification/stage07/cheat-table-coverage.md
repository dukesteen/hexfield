## Signed-admission status

Signed admission and detection timing are required, not optional. Use short traces
at genuine certified parents rather than another full game for each attack:

1. Duplicate, substituted and re-keyed deck passes reach `applyDeckPass` with
   actor signatures and fail before advancing. Duplicate outputs are rejected
   for each actor in both shuffle and lock phases; the unchanged input then
   accepts the genuine pass. All seven setup tests passed. These are signed
   pass-admission checks, not a full malformed-ceremony browser test.
2. Wrong partial unlocks and false development-card claims have signed input
   at their real operations and certified findings. The unlock trace captures
   a contributor-signed false proof during an active draw; the card trace
   captures an owner-signed false claim against a genuinely dealt Knight, with
   a valid reveal proof bound to that false claim. Both preserve card state
   and strictly replay the certified findings.
3. The live bad-sealed-opening, wrong-index, and false-dispute traces in
   `steal-replica.test.ts` each certify their attributable finding. Wrong-index
   evidence names the victim signer; false-dispute evidence names the thief.
   None commits a steal result, and the traces preserve private hands. They do
   not establish outer proposer exclusion.
4. The live false-count trace in `count-replica.test.ts` passed: both peers
   certify the victim finding without applying the false count, then complete
   the genuine contribution after restore. The separate live overspend trace
   in `cheat-live-admission.test.ts` certifies an owner finding at a
   replayable certified parent. It does not establish proposer exclusion or
   cover every spend-command variant.
5. The signed bad-recovered-master trace in
   `recovery-custody-mismatch.test.ts` now admits a unanimous certified void,
   replays it, rejects later entries and leaves the winner unset. The
   [implementation review](recovery-void-implementation-review-disposition.md)
   records the private-share checks and signing protections. This satisfies
   the chosen private recovery outcome at certified admission; it does not
   claim a live malicious-browser trace or public proof of dealer misconduct.

The [malicious-admission review disposition](cheat-admission-review-disposition.md)
records the exact scope and passing checks for the existing overspend admission
and bad-sealed-opening traces. New rows should cite their execution evidence
before being marked complete.

## Beacon distribution check

`packages/protocol/src/beacon-distribution.test.ts` calls the production `randomDerivations.derive` path for 100,000 deterministic operation contexts using a fixed 32-byte test beacon output. It counts each die independently, computes Pearson chi-square with five degrees of freedom, and checks against the predeclared 20.515 threshold (upper-tail probability 0.001) for each die. It also tests the 2d6 sum distribution with ten degrees of freedom against the predeclared 29.588 threshold. The focused run completed in about 1.9 seconds, so the original 100,000-round sample is retained without adding game simulations or reducing the requested count. This is a deterministic sampler-distribution check; it does not claim to establish all beacon transcript or adversarial unbiasability properties, which have separate protocol tests.
