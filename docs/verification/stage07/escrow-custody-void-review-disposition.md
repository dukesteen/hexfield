# Escrow-custody void review disposition

The [source-only review](escrow-custody-void-review-raw.md) used the [pinned excerpts](escrow-custody-void-review-input.md) and [source hashes](escrow-custody-void-review-manifest.sha256), with tools and MCP disabled. The raw response is unchanged. No production code changed during the review.

After the pinned snapshot, the focused test strengthened its final assertion from generic rejection to the exact `recovery-check` error. This does not change the reviewed void proposal.

The [focused certified trace](../../../packages/protocol/src/recovery-custody-mismatch.test.ts) passes. Four humans sign genesis. An old-quorum certificate authorizes recovery before any holder releases a share. Three authenticated releases reconstruct the scalar behind the dealer's signed `masterPub`; that scalar fails the signed beacon-tip check. The honest recoverer writes no private record or activation check, and an activation without its check fails.

The review's privacy finding is valid. Publishing the reconstructed scalar would let anyone with the public genesis derive the departed holder's encryption key and open the holder's sealed shares of other dealers. This extends exposure from authorized recoverers to every reader of the log and weakens other seats' escrow threshold. Existing takeover consent does not explicitly authorize that broader disclosure. The proposed master-carrying void should not ship under the current policy.

A scalar-free quorum-certified void could safely end the pending game, but public replay could verify only the certificate and its binding to the pending authorization. It could not independently verify the alleged HKDF key mismatch or attribute cheating to the dealer. Such a record must be labeled a quorum decision, not objective proof or a certified dealer finding. The Stage 07 dealer flag remains open until a reviewed proof method or explicit broader-disclosure policy exists.

A stricter private attestation can require every named recoverer to sign the same authorization, parent, affected dealer and mismatch kind after independently checking their own released shares. The user's chosen policy keeps both the recovered scalar and its hash private. Public replay verifies unanimous current-recoverer signatures and the certified pending authorization, but cannot independently recompute the private mismatch. This is a certified void decision under the honest-recoverer assumption, not objective public proof or a dealer cheating finding.

The remaining findings are concrete implementation requirements for any certified void: replay must install an explicit terminal state and reject all later game entries; the session must report void separately from an engine winner and avoid a successful audit claim; the statement must bind the exact pending authorization, parent and affected original dealer; verification must use the certified parent's deck ledger and distinguish four derived-key mismatch codes from malformed context or supplied input. `produceRecoveryCheckFromShares` wipes the reconstructed scalar on failure, so a public-evidence path would need a separate authenticated reconstruction and wipe boundary.

The post-review protocol implementation adds that scalar-free unanimous `recovery-void` transition, durable private attestation before output, a replayed terminal marker, and a distinct void session status. The focused trace certifies the void and rejects all later entries while leaving the engine winner unset. No `CHEAT_PROOF` or dealer attribution is created. Worker and UI presentation of the terminal status are separate integration work; the objective public dealer-fault row remains open under the chosen privacy policy.
