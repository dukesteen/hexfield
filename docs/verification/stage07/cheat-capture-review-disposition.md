The [raw Claude review](cheat-capture-review-raw.md) used the [pinned excerpts](cheat-capture-review-input.md) and [source manifest](cheat-capture-review-manifest.sha256), with tools disabled. The input includes the `replicated-log.ts` change, the extractor, verifier and historical-replay paths, and selected assertions from the capture and bad-beacon-reveal tests. The raw output is unchanged. This disposition checks each finding against the complete local source. No production code changed during the review.

| Raw finding                                                                                    | Disposition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. `cheatCandidateId` merges distinct proofs from one seat and kind                            | Intended first-finding bound, not a demonstrated loss of the only provable evidence. `cheatCandidateId()` has always used `seat/kind`; `firstCheatFindings()` also retains one certified finding per seat and kind. `rememberCheatClaim()` verifies and durably stores the first candidate before `has(id)` can suppress a later one. The first candidate remains eligible across head changes: `replay.ts` checks its exact certified parent and historical controller, then replays that parent if its 16-context cache missed. Cache eviction is not evidence loss. A stalled proposer or absent quorum also blocks the proposed replacement claim. Multiple same-kind proofs would need a separate product requirement and different storage bound. |
| 2. Historical `CHEAT_CLAIM` skips the current-key prefilter                                    | Correct historical behavior. The receive branch rejects future parent sequences before work, checks the local candidate/finding maps, and allows at most three new expensive cheat requests per peer per 10 seconds. `verifiedCheatClaim()` routes older claims to `verifyHistoricalCheat`; that callback checks the exact parent hash and replay-derived controller timeline before full replay. Running `authenticatedCheatSigner()` with today's controller against an older claim would incorrectly reject evidence after a seat change. The branch's remaining error text says "genesis signer" and is cosmetic.                                                                                                                                   |
| 3. Capture holds a receive-queue slot through proof verification                               | Real bounded latency exposure, not an unbounded work path in the cited code. `captureRejectedProofs()` runs in the serialized receive task, after a nonfatal rejection, and can examine at most six extracted artifacts. Only authenticated current voters reach it; the raw frame limit is 256 KiB, ingress holds at most eight messages per peer and 32 total, and the capture budget is three distinct requests per voter per 10 seconds. This still needs a Chromium-worker timing check against heartbeat and voting deadlines. Until measured, do not claim that the bound prevents visible stalls.                                                                                                                                               |
| 4. `captureCertifiedDelivery()` calls `offerAvailableInput()` before its caller calls it again | No recursive or concurrent call was found. The two calls are awaited in order. `maybePropose()` checks whether the current controller already has a proposal for that round, and the second call uses normal non-retransmit preparation. It may repeat cheap preparation or reads, but the excerpts do not establish an extra signed proposal or unsafe delivery. A targeted call-count test would settle performance if this path becomes hot.                                                                                                                                                                                                                                                                                                         |

The extractor preserves malformed _inner_ proof data inside a bounded signed outer artifact. `decodeMessage()` still caps the raw wire bytes and applies the strict capture envelope. Every candidate then passes `encodeCheatCandidate()` and `verifiedCheatClaim()` before `putIfAbsent()`; the full verifier requires the exact certified parent and objectively attributes the offender. `rememberCheatClaim()` persists before broadcasting, and restore revalidates durable bytes. The extra `PROPOSAL` capture attempt and the outer rejection hook share the same `capture/<frame hash>` budget key, so the second pass is suppressed.

No confirmed security or consensus defect remains from this scoped review. The open check is measured proof-verification latency under the stated per-voter budget; the new integration test proves one bad signed beacon reveal becomes a certified finding without changing the owed beacon outcome, but it does not measure worst-case queue delay.
