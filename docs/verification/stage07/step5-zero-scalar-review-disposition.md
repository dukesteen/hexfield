# Zero-value review disposition

The [first source-only review](step5-zero-scalar-review-raw.md) confirmed the algebra and Noble's nonzero multiplication path. It found that computing each `sP` separately still produced an identity intermediate at `s = 0`, and that bit preparation conditionally performed `target - G`. The code now combines positive G/H terms before subtracting corrections and computes `target - G` for either bit. The [follow-up review](step5-zero-scalar-followup-raw.md) confirmed both operation-count fixes and unchanged proof equations.

After the follow-up snapshot, `pedersenCommit` dropped two redundant scalar-to-byte conversions. `zeroSafeProductTerms` already rejects noncanonical scalars; the conversions did extra magnitude-dependent work and discarded their output. The new helper uses the former `pedersenCommit` error wording for invalid scalar values. A range test checks Pedersen outputs at zero and both high scalar boundaries. Final source hashes are in the [manifest](step5-zero-scalar-final-manifest.sha256); 65 focused crypto and protocol tests, package build, type-aware lint, formatting, and diff checks pass.

The fix removes the frequent zero-scalar shortcut for hidden counts, one-hot bits, range values, and Pedersen blindings. It does not make JavaScript constant time. Noble's table choices, BigInt arithmetic, and secret-dependent proof control flow remain possible timing channels. The review noted that a fine-grained same-origin observer could distinguish the heavier real CDS branch from simulated branches by position; no remote exploit was demonstrated. That broader issue needs a separate threat-model and design review. The [headed timing](step5-zero-scalar-headed-timing.json) measures performance, not side-channel resistance.
