# Local implementation review

The [Claude attempt](recovery-implementation-review.md) hit its session limit and produced no review. The root agent inspected the coordinator, lifecycle transitions, IndexedDB adapter and private replay implementation. This document distinguishes that inspection from an independent Claude review.

A confirmed crash gap existed between retaining a disclosure record and committing whole-ceremony retirement. A failed retirement write left the registry active, so a restarted coordinator could enqueue another approval. A regression uses a real dealer-signed invalid ciphertext and a retirement CAS failure; it reproduced that behavior before the fix. The correction treats retained pre-consent disclosure as an outgoing-action barrier and finishes retirement before any further traffic, including genesis consent. Exact complaint retries remain possible after successful retirement. A full valid four-human final draft verifies that consent is blocked by this barrier, rather than failing for an unrelated malformed draft. The focused coordinator file passes all four tests after the correction. Dispute intake uses the raw registry phase so that repeated and additional post-consent disclosures remain persistable; outgoing actions use the stronger disclosure barrier.

Private reconstruction first authenticates the supplied history, then validates provided masters against the genesis keys and complete deck setup. It checks every owned human beacon link/extension and rebuilds only owned hands through the existing private driver. Tests compare rebuilt hands to real deal and steal histories. This is not share-release authorization, controller activation or complete end-game audit.

The browser store resolves writes after transaction completion, uses one native readwrite transaction for CAS, and shares ceremony locks across same-origin contexts. Unit tests cover abort after request success, concurrent connections, schema errors and unavailable locks. The separate [Chrome check](native-storage-check.md) confirms native two-worker CAS, connection reopening and Web Locks. It does not claim power-loss durability.

The review-attempt manifest remains the historical input snapshot. `escrow-ceremony.ts` and its test changed afterward to address the confirmed crash bug and add genuine bad-envelope retry coverage. The final local-check manifest records the corrected source. Claude implementation review remains pending.
